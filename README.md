# bg2max

Мини-приложение под Android, транслирующее показатели глюкозы крови из xDrip+ в мессенджер MAX.

> ⚠️ **BG2MAX — не медицинское изделие.** Не принимайте по его сообщениям решений о лечении и не полагайтесь на него как на систему оповещения: данные могут опаздывать, теряться или быть неверными. Полный текст — в разделе [«Отказ от ответственности»](#отказ-от-ответственности); приложение показывает его при первом запуске и не открывается без согласия.

## Два варианта приложения

Из одного кода собираются два APK, их можно поставить на один телефон одновременно:

| Вариант | Пакет | Как отправляет |
|---|---|---|
| **BG2MAX** (`bot`) | `com.bg2max.app` | через MAX Bot API от имени своего бота — нужен бот с business.max.ru и его токен |
| **BG2MAX Ответ** (`reply`, экспериментальный) | `com.bg2max.app.reply` | кнопкой «Ответить» в уведомлении MAX — от имени аккаунта MAX на этом телефоне; бот, токен и доступ в интернет не нужны |

Общий код — `app/src/main`, отличия — `app/src/bot` и `app/src/reply`. Ниже описан вариант `bot`; про `reply` — раздел [«BG2MAX Ответ»](#bg2max-ответ-экспериментальный).

## Как это работает

1. Приложение работает как foreground-сервис и слушает локальный broadcast-протокол xDrip+ (`com.eveningoutpost.dexdrip.BgEstimate`) — без Bluetooth, без облака, только на устройстве.
2. При получении нового показания оно конвертирует мг/дл в ммоль/л, определяет стрелку тренда и отправляет сообщение через MAX Bot API в заданный чат.

## Требования

- Установленный и настроенный **xDrip+** с включённой опцией «Локальная трансляция данных» (Настройки → Настройки интеграций с приложениями). В поле «Установить получателя» указать `com.bg2max.app` — это ограничивает broadcast только нашим приложением, поле необязательное, но рекомендуется.
- Бот в MAX, созданный на `business.max.ru` (нужен подтверждённый профиль организации, ИП или самозанятого — завести бота от обычного личного аккаунта нельзя), и его токен.

## Настройка в приложении

1. Вставить токен бота.
2. Написать боту что-нибудь в личном чате в MAX **или** добавить бота в нужную группу, затем нажать «Определить Chat ID». Групповые чаты поддерживаются так же, как личные — сообщения шлются тем же способом (`chat_id` через `/messages`).
   - `GET /updates` (long polling), которым пользуется эта кнопка, по документации MAX «ограничен по сроку хранения событий» — событие о добавлении бота в группу может не успеть дойти. Если кнопка ничего не нашла, введите chat ID вручную: откройте нужный чат на `web.max.ru` и скопируйте число в конце адресной строки — это и есть chat_id.
3. Сохранить настройки и включить тумблер трансляции.

Кнопка «Симулировать показание» позволяет проверить всю цепочку (конвертация → отправка в MAX) без установленного xDrip+.

## BG2MAX Ответ (экспериментальный)

Приложение читает уведомления MAX (`NotificationListenerService`), запоминает кнопку «Ответить» из уведомления **выбранного** чата и при каждом показании xDrip+ «нажимает» её с текстом показания. Сообщение уходит от аккаунта MAX на этом телефоне (например, ребёнка) в чат с получателем (например, родителем). Сеть использует само приложение MAX — `BG2MAX Ответ` не имеет разрешения на интернет.

Настройка — на главном экране по шагам:
1. **Доступ к уведомлениям.** Если APK поставлен файлом, Android 13+ может пометить настройку как «ограниченную»: О приложении → ⋮ → «Разрешить ограниченные настройки». На Xiaomi/HyperOS этого пункта нет — переустановить APK через SAI (Split APKs Installer).
2. **Чат.** Получатель пишет на телефон любое сообщение в MAX → «Выбрать чат» → выбрать из списка чатов, от которых были уведомления. Ответы уходят только в этот чат (совпадение имени и типа: личный/группа).
3. **Работа в фоне:** отключить оптимизацию батареи; на Xiaomi — «Автозапуск» и «Нет ограничений» для BG2MAX Ответ и для MAX.
4. В xDrip+ в поле «Установить получателя» указать `com.bg2max.app.reply` или оставить пустым.

Ограничения:
- Кнопка живёт только в памяти процесса. После перезапуска приложения или телефона, а также если MAX отменит кнопку, нужно новое сообщение из выбранного чата (или его уведомление должно остаться в шторке). Пока его нет, показания не уходят; последнее откладывается и отправляется, если кнопка появится в течение 10 минут. Состояние видно в постоянном уведомлении.
- Если уведомление другого чата принесёт тот же `PendingIntent`, что у сохранённой кнопки, отправка блокируется до нового сообщения из выбранного чата (защита от отправки не туда).
- «Передано в MAX» в журнале значит только, что кнопка нажата; дошло ли сообщение — видно в чате получателя.
- Чат с получателем не должен быть без звука, уведомления MAX должны быть включены.

Журнал хранится в файле (до ~2 МБ) и отправляется кнопкой «Поделиться журналом». В нём: каждое уведомление MAX (имя чата и id, без текста), каждая отправка с состоянием экрана, Doze и сети («интернет не подтверждён» — Android не достучался до своего сервера проверки, типично при белых списках), перезапуски сервиса и слушателя.

## AndroidAPS: IOB и COB (в разработке)

Приложение принимает broadcast AndroidAPS `info.nightscout.androidaps.status` (модуль AAPS «Samsung Tizen», `TizenPlugin.kt`) — в нём есть IOB, COB, данные помпы и другое. Пока это только диагностика: последний пакет целиком показывается на главном экране в блоке «Данные AndroidAPS», в журнал пишется строка с IOB/COB. В сообщения MAX эти данные ещё не попадают.

Чтобы AAPS начал присылать данные: в AAPS → Конфигуратор → раздел «Синхронизация» включить модуль **Samsung Tizen**.

## Сборка

```
./gradlew assembleBotDebug      # BG2MAX (бот)
./gradlew assembleReplyDebug    # BG2MAX Ответ
```

APK появятся в `app/build/outputs/apk/bot/debug/bg2max-bot-<версия>-debug.apk` и `app/build/outputs/apk/reply/debug/bg2max-reply-<версия>-debug.apk`.

## Версии

История изменений — в [CHANGELOG.md](CHANGELOG.md). Текущая версия видна в заголовке приложения.

Выпуск новой версии:
1. В `app/build.gradle.kts` увеличить `versionCode` на 1 и поднять `versionName` (у варианта `reply` — свои `versionCode`/`versionName` в блоке `productFlavors`) (SemVer: исправление → `1.1.1`, новая возможность → `1.2.0`).
2. Перенести пункты из раздела «Не выпущено» в `CHANGELOG.md` под новый номер с датой.
3. Закоммитить и поставить тег: `git tag v1.2.0 && git push --tags`.

## Стек

Kotlin, Android SDK (minSdk 26, targetSdk 34), без сторонних сетевых библиотек — HTTP-запросы к MAX Bot API через `HttpURLConnection` (вариант `bot`); `NotificationListenerService` + `RemoteInput` (вариант `reply`).
